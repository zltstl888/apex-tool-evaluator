# Security Policy

## Scope

Report vulnerabilities in the bundled validator, tests, or instructions that could cause unexpected writes, secret exposure, unsafe permission grants, or misleading adoption decisions.

Do not include real credentials, customer data, or exploit payloads containing sensitive information in a public report.

## Reporting

Use GitHub private vulnerability reporting from the repository's **Security** tab. Do not open a public issue containing exploit details, credentials, customer data, or a private system path.

If private reporting is temporarily unavailable, open a public issue containing only a request for a private contact channel. For an active secret exposure, revoke or rotate the credential first and never paste it into the issue.

## Supported versions

| Version | Supported |
| --- | --- |
| Latest tagged release | Yes |
| Older releases and `main` snapshots | No |

The GitHub release page is the canonical source for the latest supported release.
